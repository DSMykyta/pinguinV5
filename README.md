# Pinguin Next

**Tabula rasa:** лише мінімальна основа, документація та автоматичні перевірки. Жодних старих модулів чи бізнес-логіки.

- **main** — поточний Production;
- **reserve** — попередня стабільна версія;
- **legacy** — незмінний старий Pinguin V5;
- **work** — нова модульна розробка (Preview).

## Стандарт — перед кодом

Перш ніж створювати новий компонент, прочитай [docs/conventions.md](docs/conventions.md). Усі власні файли, CSS, назви функцій, події та модулі мають бути узгоджені. Перший запланований модуль — генератор HTML/BR-таблиць, після створення мінімального Shell і спільних UI-компонентів.

## Запуск і перевірка

~~~bash
npm install
npm run dev
npm run check:naming
npm run check
~~~

Перший check перевіряє назви файлів і CSS, другий додатково виконує збірку Vite. GitHub Actions запускає перевірку в work та під час PR до main. Семантичні назви JavaScript-функцій і якість архітектури перевіряються також під час code review.
