# Універсальний шаблон сторінок Pinguin Next

Сторінки мають однакову оболонку; різні інструменти визначають тільки свій контент.

## Ієрархія

```text
Shell
├─ Sidebar (основні сторінки, тема)
├─ Workspace
│  ├─ Header: H1 — назва маршруту; справа — пошук і aside control
│  ├─ Local navigation: вкладки розділу, якщо вони є
│  ├─ Main
│  │  └─ Page View: H2 — назва секції, далі вміст
│  └─ Footer (окрема порожня смуга 56px, без видимого вмісту)
└─ Aside (floating / pinned)
```

Мобільний backdrop — службовий елемент Shell для відкритої панелі, **не** окрема зона документа.

## Незмінні правила

1. Заголовок маршруту H1 один, у Shell. Активний таб **не переписує** його.
2. Вкладки в глобальному слоті між шапкою та Main; не в sidebar, не по центру header.
3. Основна секція використовує `createPageView({ title })` з `src/ui/page/page.js`: H2 і `body`.
4. Однакова ліва вісь H1, вкладок та H2 задається токеном `--pg-workspace-gutter` у `shell.css`, без локальних винятків.
5. Робоча секція використовує доступну ширину (без фіксованого max-width: 800px), щоб майбутні таблиці не були штучно вузькими.
6. Пошук праворуч є спільним полем **без випадної панелі**: Enter активує найкращий збіг, Escape очищує поле; індекс може розширюватися даними активної сторінки.
7. Footer — справжня порожня зона висотою `--pg-sidebar-compact-width` (56px), а не `margin` центрального полотна.

## Тимчасова перевірка меж (2026-11-05)

До затвердження геометрії `.pg-shell__content` тимчасово має світло-сірий фон (`--pg-color-hover`) і скруглення `18px`. Демонстраційний вміст вкладок `/tools` приховано, але логіка навігації та aside продовжує працювати. **Це лише режим перевірки**, не постійна палітра; після схвалення відновити прозору робочу область і вміст. Повернені погоджені метрики попереднього Shell: шапка `60px`, верхній padding основної області `40px` (desktop), її горизонтальні відступи `clamp(20px, 5vw, 72px)`; на телефоні `32px 20px 56px`. Праву групу кнопок тримати `position: fixed; top: 10px; right: 12px`, незалежно від закріплення aside. Зміна структури сторінки не дає дозволу змінювати ці значення.

## Узгоджена система координат (зовнішні зони)

Спільна одиниця для компактної лівої панелі, порожньої правої смуги й порожнього підвалу — `--pg-sidebar-compact-width: 56px`. Основна область **не має зовнішніх margin**.

- **Зліва:** реальна колонка sidebar — 56px у згорнутому режимі, 228px у розгорнутому.
- **Справа:** у незакріпленому режимі реальна порожня колонка Shell — 56px.
- **Знизу:** окремий `footer.pg-shell__footer` у Workspace — порожня смуга висотою 56px.
- **Праворуч із закріпленим aside:** резервується 302px ширини aside, незмінні 12px до правого краю вікна та **8px між робочим полотном і aside**. Це стільки ж, скільки між правим краєм видимої кнопки sidebar та лівим краєм полотна: порівнюємо відстань між елементами, а не ширину колонки. Зазор задається сіткою Shell, а не `margin` робочої області; вигляд і координати aside не змінюються.
- **Зверху:** шапка 60px і ряд вкладок залишаються над полотном. Aside починається від `top: 64px` у відповідному CSS.
- **Всередині полотна:** початковий padding `40px clamp(20px, 5vw, 72px) 72px` збережено. Сірий колір і заокруглення 18px лише тимчасово показують межі.

H1 та вкладки вирівнюються без додаткового зсуву (`--pg-workspace-chrome-inset: 0px`) безпосередньо з лівим краєм полотна. Позиції правих кнопок фіксовані незалежно від закріплення aside.

На мобільному sidebar і aside працюють як накладені панелі; структурний footer зберігає 56px, не додаючи дві штучні бічні колонки в вузький екран.

Перевірка реальних координат та перемикання станів: `tests/e2e/page-layout.spec.js`.

## Візуальний зазор і геометрія шапки

Порівнюємо **реальні краї компонентів**, а не ширину порожніх колонок. У collapsed sidebar ширина колонки 56px; кнопка меню займає 40px та має по 8px зовні. До полотна від кнопки лишається 8px. При закріпленні aside його ліва межа також відсувається від полотна на **8px** за рахунок третьої колонки Shell. Той самий тест порівнює обидва реальні проміжки. H1 та вкладки починаються на осі лівого краю полотна без додаткових 16px. Мобільний заголовок має власний простір для окремої кнопки меню; позиції пошуку й aside-toggle не змінюються.

## Незалежні робочі панелі вкладок (2026-11-05)

`createTabs()` керує не лише активною кнопкою, а й **власним DOM-розділом кожної вкладки** у `.pg-tabs__content`. `Таблиці` та `Текст` не можуть використовувати один і той самий активний тестовий вміст без розділення. Під час UI-тестів усі демо належать лише своїй панелі та зникають при переході на іншу вкладку. `src/shell/shell.css` і сітка Shell не змінюються.
