# Reveal Panel — універсальна поява та вихід панелей

Модуль: \`src/ui/reveal-panel/reveal-panel.js\`, стилі: \`reveal-panel.css\`.

**Призначення.** Показує довільний HTML-вміст зі сторони \`top\` або \`bottom\`: панель заїжджає у своє місце й у зворотному напрямку повністю виходить за межу. Бібліотека **не знає**, чи її вміст — вкладки, пошук, фільтри, меню або інший інструмент. Використовується лише там, де потрібне контекстне тимчасове керування.

\`\`\`js
import { createRevealPanel } from '../../ui/reveal-panel/reveal-panel.js';
const reveal = createRevealPanel({ element: toolbarElement, direction: 'top', focusTarget: persistentButton });
reveal.setVisible(true);
reveal.setVisible(false, { onHidden: () => toolbarElement.replaceChildren() });
reveal.destroy();
\`\`\`

Контракт: виклик \`setVisible(false)\` лишає DOM дочірніх елементів до завершення виходу. У стані \`leaving\` панель \`inert\` та \`aria-hidden=true\`, фокус повертається назовні. Після анімації вузол отримує \`hidden\`, і тільки тоді викликається \`onHidden\`. Повернення \`setVisible(true)\` посеред виходу **скасовує** завершення і старий callback; CSS переходить з поточного положення. Коли \`prefers-reduced-motion: reduce\`, панель ховається відразу. \`destroy()\` прибирає таймери й слухачі, DOM залишається у власності викликачів.

Анімація працює через \`opacity\` і \`transform\`, використовує наявні \`--pg-duration-layout\`, \`--pg-duration-normal\`, \`--pg-ease-layout\`. Ніяких нових бібліотек, таймерів для відкриття, висоти або рамок. Реальна панель займає лише свій звичайний розмір.

**Інтеграція Shell.** \`.pg-shell__context-tools\` — єдиний контейнер для \`pageActionsHost\` і наявного \`search.element\`. Панель з'являється, якщо сторінка передала дії або доступний контекст пошуку; зникає, якщо обидва відсутні. Два існуючі callbacks, \`setHeaderActions\` і \`setSearchContext\`, агрегуються за одну microtask, тому перемикання вкладки не викликає проміжних суперечливих станів. Видимі елементи лишаються в DOM під час виходу, а при повторному показі вихід скасовується. Кнопка контекстного меню лишається на звичному місці, за межами рухомого контейнера. Сам Shell не містить специфічних відомостей про \`Макети даних\`.

**Порівняння з Toast.** \`src/ui/toast/toast.js\` використовує схожий патерн станів \`entering → visible → closing\` і переходи \`transform/opacity\`, але Toast керує FIFO, стеком, hover-expand, автозакриттям, поверненням фокусу та окремим напрямком виходу вниз. Виносити весь Toast у Reveal Panel недоцільно: вийде універсальна абстракція з великою кількістю несумісних параметрів, буде порушена відповідальність модулів. Перевикористані **токени руху та підхід до керування станами**, але кожен компонент залишається незалежним.

Перевірка: \`tests/e2e/reveal-panel.spec.js\` і інтеграційні тести Shell; покривають стани, зворотний рух, втрату фокусу, елементи DOM до завершення виходу, швидке перемикання вкладок, reduced motion, мобільний інтерфейс.


## Нижня контекстна панель Shell (2026-11-09)

Той самий `createRevealPanel` підключений до `.pg-shell__footer-panel` із `direction: 'bottom'`. Постійний 56px `footer` лишається в Shell незалежно від вкладки. При `setFooterContent(pagination)` вже створений Pagination і page-size FAB монтуються в єдиний рухомий слот; для контекстного підвалу вхід — **знизу**, вихід — **униз**. Після завершення виходу дочірній DOM від'єднується, а не передчасно видаляється. При повторному відкритті під час exit вихід скасовується, зберігається той самий Pagination і його поточна сторінка. Власник Shell не знає назв вкладок, а FAB бере участь в русі разом із пагінацією. `footer[data-pg-has-content]` позначає бажану видимість, `data-pg-reveal-exiting` тимчасово тримає рамку протягом виходу. Усі анімації й reduced-motion надає спільний компонент; окремих keyframes для підвалу немає.
