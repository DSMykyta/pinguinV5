# Pinguin Next — Toast / Snackbar

Статус: специфікація спільного UI-компонента. Рішення прийняті після дослідження `legacy`, WAI-ARIA, WCAG та практик Material. Див. [базу UI](overview.md).

## 1. Завдання

Короткий зворотний зв'язок про **вже здійснену** дію: збереження, копіювання, оновлення, помилку запиту. Toast не замінює діалог підтвердження, повноцінну помилку форми або журнал подій. Критичні інструкції не можуть існувати лише в короткому Toast.

Вимоги власника: той самий нижній лівий кут, що у V5, `left: 20px; bottom: 20px`. Toast **може тимчасово перекривати** нижню ліву кнопку теми; нічого у Shell не пересуваємо. Після зникнення повідомлення кнопка знову вільна.

## 2. Аудит legacy

- `legacy/js/components/feedback/toast.js`: `showToast(message, type, durationOrOptions)`; створює єдиний контейнер; має action, автозакриття, подвійну `requestAnimationFrame`-анімацію.
- `legacy/css/components/overlays/toast.css`: fixed `bottom: 20px; left: 20px`; темна інверсна поверхня; min-width 288px; max-width 600px; тінь, анімація; кілька Toast утворюють вертикальний стек.
- Є численні використання у сторінках: успішне збереження, помилки API, оновлення таблиць, сповіщення про завдання з дією.
- Недоліки: legacy класи без `pg-`; довільні параметри; дві різні default duration; `0` не працює у варіанті з options через `||`; немає паузи на hover/focus, захисту від переповнення, надійного cleanup і гарантії при reduced motion. Стан залежить від CSS-класів.

**Зберігаємо:** позицію, інверсну нейтральну поверхню, короткий меседж, необов'язкову дію, плавність. **Переробляємо:** контракт, таймери, оголошення, чергу, кольорові ролі, cleanup.

## 3. Зовнішні джерела та рішення

| Джерело | Перевірена рекомендація | Рішення Pinguin |
| --- | --- | --- |
| [MDN — status role](https://developer.mozilla.org/en-US/docs/Web/Accessibility/ARIA/Reference/Roles/status_role) | Не переміщати фокус, `status` є ввічливою live region | Звичайні повідомлення оголошуються через попередньо створену `role=status` region |
| [MDN — alert role](https://developer.mozilla.org/en-US/docs/Web/Accessibility/ARIA/Reference/Roles/alert_role) | `alert` лише для термінових повідомлень; кнопки не повинні бути вкладені в alert | Помилки можуть мати окреме текстове `role=alert`; дії і хрестик поза live region |
| [MDN — live regions](https://developer.mozilla.org/en-US/docs/Web/Accessibility/ARIA/Guides/Live_regions) | Надійніше створити live region до оновлення тексту | Два невидимі постійні announcer, окремо від видимого повідомлення |
| [W3C — WCAG 2.2.1](https://www.w3.org/WAI/WCAG22/Understanding/timing-adjustable.html) | Користувач має достатньо часу; коротке повідомлення допустиме, якщо інформація доступна й інакше | Інформаційні Toast короткі, дія — без автоматичного тайм-ауту |
| [Material — Snackbar](https://m3.material.io/components/snackbar/overview) | Короткий текст, не більше однієї дії, без перенесення фокуса; послідовний показ | Один видимий Toast + FIFO-черга, одна необов'язкова action |
| [Material Components — accessibility](https://github.com/material-components/material-components-web/tree/master/packages/mdc-snackbar) | Оголошувати повідомлення, Escape для сфокусованого snackbar | Escape закриває Toast, якщо клавіатурний фокус на його елементі |
| [Material UI — Snackbar accessibility](https://mui.com/material-ui/react-snackbar/) | Escape — можливість закриття | Використовуємо Escape, не перехоплюючи глобально інші меню |

Це рішення **свідомо відхиляється** від стеку кількох одночасних Toast у legacy: стек заважає читати та може довго перекривати кнопки. Pinguin показує один Toast, решта чекають. Позицію legacy зберігаємо, хоча деякі Material-гайди радять уникати накладання на FAB: тут тимчасове перекриття кнопки теми погоджено власником.

## 4. Геометрія й стилі

- Контейнер: `.pg-toast-host`, `position: fixed; left: 20px; bottom: 20px`, `z-index` вище кутових кнопок; не займає місця у grid Shell.
- Видимий елемент: `.pg-toast`, висота від 48px, ширина за вмістом від 288px до 480px з обмеженням `100vw - 40px`.
- Заокруглення: 12px; `gap`: 12px; padding: 12px 14px; компактний шрифт 13px, line-height 1.4. Без декоративних градієнтів.
- Кольори: інверсна нейтральна поверхня, акцент **лише на семантичній піктограмі й action**. Немає кольорових коробок для кожного стану. Значення кольорів — тільки `src/styles/tokens.css`, з темними/світлими варіантами.
- Анімація: близько 180ms, невеликий вертикальний рух та opacity; на `prefers-reduced-motion: reduce` — миттєва поява/закриття.
- На вузьких екранах компонент уміщується у viewport, довгі слова переносяться; не перекриває верхню шапку навмисним повноекранним шаром.
- Стилі лише в `src/ui/toast/toast.css`; не додавати toast-правила у `shell.css` або `features`.

## 5. Поведінка

- Типи: `info` (за замовчуванням), `success`, `warning`, `error`; `data-pg-type` тільки для вигляду, `data-pg-state`: `entering`, `visible`, `closing`.
- Default timeout: info/success 4000ms, warning 5000ms, error 6000ms; `duration: 0` означає ручне закриття. Якщо передано action, за замовчуванням `duration: 0`.
- Для звичайного Toast автоматичний timer паузиться при hover, focus усередині та прихованій вкладці; після відновлення продовжується із залишком часу.
- Дія одна: `{ label, onClick }`; поруч окрема доступна кнопка `Закрити повідомлення`. Action та її обробник працюють один раз. Хрестик на всіх типах.
- Один видимий Toast; FIFO до 8 очікувань; повтор однакового тексту/типу **без action** у видимому Toast або черзі зливається в одне повідомлення. При переповненні нові неінтерактивні повідомлення відхиляються, щоб не затоплювати UI; повідомлення з діями зберігаються в черзі.
- Немає автоматичного переведення фокуса на Toast. Якщо Toast видалено, коли фокус був на його кнопці, фокус повертається до попереднього елемента, коли це можливо.
- Зафіксована в робочому інструменті помилка не повинна зникати разом із Toast; Toast — додатковий короткий сигнал.
- `textContent` для користувацького тексту, жодного вставлення довільного HTML.

## 6. API та життєвий цикл

```js
// Лише bootstrap, один раз (src/main.js)
const disposeToasts = mountToasts();

// У будь-якому інструменті — імпорт зі спільного UI:
showToast('Зміни збережено', { type: 'success' });
showToast('Не вдалося надіслати', {
  type: 'error',
  action: { label: 'Повторити', onClick: retryUpload },
});
// Якщо потрібно закрити повідомлення з коду:
const handle = showToast('Триває імпорт', { duration: 0 });
handle.dismiss();
```

Публічні експорти `mountToasts()` та `showToast(message, options)`. `mountToasts()` явно монтує singleton; його dispose прибирає DOM/listeners/timers і звільняє singleton для повторного HMR. `showToast` не створює DOM сам при випадковому імпорті. Інструменти не звертаються до `window.showToast`.

## 7. Перевірки готовності

1. Відповідність CSS-неймінгу, токенам, доступності й `npm run check`.
2. Позиція 20/20 px на desktop, кнопка теми не зсувається; Toast її тимчасово накриває, потім повністю видаляється.
3. 4 семантичні стани, HTML без ін'єкцій, одна дія, близька кнопка, робота з довгим повідомленням.
4. FIFO, дедуплікація, переповнення, повторне монтування, cleanup після destroy/HMR.
5. Пауза timer для pointer/focus/hidden, `duration:0`, Escape, повернення фокуса.
6. Світла й темна тема, mobile, reduced motion, скринридер.
7. Немає UI-демонстрації, що спотворює схвалений скелетон; Playwright активує компонент програмно, без додавання фальшивих кнопок.

## Межі

Toast не є діалогом підтвердження, лоадером із прогресом, віджетом завдань чи системою історії сповіщень. Такі компоненти створюються окремо після погодження.
