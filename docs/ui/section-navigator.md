# Section navigator — переходи на межі блоку

Дослідження й контракт від 2026-11-08. Універсальний UI для послідовності довільних секцій: «Основне → Фото → …». Власник задає порядок і передає готові DOM-вузли. Секції не імпортують одна одну; навігатор не знає про товари, зображення, збереження чи конкретні редактори.

## Дослідження

### Що саме відтворюємо

На референсі після завершення вмісту є окремий індикатор наступної дії. Це boundary / pull navigation: продовження руху після межі відкриває наступний блок. Статичний скриншот не визначає точні пороги, тривалість чи механіку застосунку; наведені нижче значення — наші початкові проєктні рішення.

| Підхід | Переваги | Обмеження / рішення |
| --- | --- | --- |
| CSS scroll snap | Нативне прокручування, мінімум JS | Добрий для стрічки карток. Довгі редактори різної висоти й перевірка переходу потребують іншого контракту. |
| Перетягування всієї поверхні мишкою | Близьке до сенсорного жесту | Конфліктує з виділенням тексту й полями. Мишка перетягує тільки видиму ручку. |
| Boundary navigation + кнопки | Зберігає звичайний скрол, має явний перехід та можливість скасувати | Обрано. Додаткова прокрутка на межі, потягування пальцем / ручкою, звичайні кнопки. |

### Первинні джерела та наслідки для реалізації

1. [W3C Pointer Events 3, touch-action](https://www.w3.org/TR/pointerevents3/#the-touch-action-css-property): браузер може забрати сенсорне прокручування; зміна touch-action після початку жесту не змінює поточний жест. Ручки мають завчасний `pan-x pinch-zoom`; viewport зберігає native scroll. Для pull на його межі використано локальні Touch Events із cancelable touchmove, без глобальної заборони панорамування / zoom.
2. [MDN: wheel](https://developer.mozilla.org/en-US/docs/Web/API/Element/wheel_event): wheel та scroll — різні події; Ctrl+wheel також може означати zoom, деякі події не скасовуються. Межа визначається через scrollTop/clientHeight/scrollHeight. Zoom, горизонтальний wheel, non-cancelable події та вже оброблені події не запускають перехід.
3. [MDN: deltaMode](https://developer.mozilla.org/en-US/docs/Web/API/WheelEvent/deltaMode): дельти бувають у пікселях, рядках і сторінках. Рядки нормалізуються через обчислений line-height, сторінки — через висоту viewport. Внесок одного wheel event обмежено 60 CSS px.
4. [MDN: overscroll-behavior](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/overscroll-behavior): CSS контролює scroll chaining, але сам не виконує перехід. `overscroll-behavior-y: contain` застосовується тільки до локальної області навігатора.
5. [W3C WCAG 2.2: 2.5.7](https://www.w3.org/WAI/WCAG22/Understanding/dragging-movements) та [2.5.1](https://www.w3.org/WAI/WCAG22/Understanding/pointer-gestures): жест потребує еквівалента одним натисканням. Видимі native кнопки «Назад» / «Далі» працюють мишкою, дотиком, Tab та Enter/Space. Глобальні клавіші стрілок не перехоплюються.
6. [MDN: prefers-reduced-motion](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@media/prefers-reduced-motion): при reduce відсутні переміщення індикатора та CSS transitions; доступний статичний прогрес і текст.

Перевірено попередні `legacy/js/components/editor/editor-charm-chip-navigation.js` та `legacy/js/pages/products/products-crud-wizard.js`: їхня навігація прив'язана до старих DOM / глобальних станів. Старий код не імпортується. Новий компонент дотримується [конвенцій](../conventions.md).

## Поведінка

| Ввід | Наступна секція | Попередня секція | Підтвердження |
| --- | --- | --- | --- |
| Палець усередині вмісту | На нижній межі почати новий жест і потягнути вміст угору | На верхній межі почати новий жест і потягнути вниз | Відпустити після 88 CSS px |
| Мишка на ручці | Затиснути нижню ручку та потягнути вгору | Затиснути верхню ручку та потягнути вниз | Відпустити після 88 CSS px |
| Колесо / тачпад | Почати додаткове прокручування вниз, уже перебуваючи внизу | Почати додаткове прокручування вгору, уже перебуваючи вгорі | Накопичити 180 CSS px і зупинитися на 200 ms |
| Кнопка | Натиснути «Далі: назва» | Натиснути «Назад: назва» | Одне натискання |
| Клавіатура | Tab до кнопки, Enter/Space | Tab до кнопки, Enter/Space | Native button |

«Вниз» для колеса означає рух до нижнього вмісту. Палець при цьому рухається вгору. Перехід назад симетричний. Циклічного переходу остання → перша немає.

- Вміст спершу прокручується повністю. Wheel-серія, що почалася посеред блоку, не може активувати перехід навіть після досягнення межі; потрібна пауза 200 ms і нова серія.
- Один жест — максимум один перехід. Після зміни секції wheel має паузу захисту 600 ms; інерція не запускає ланцюжок переходів.
- Відпускання до порога, повернення нижче порога, горизонтальний жест, Escape, pointercancel / touchcancel, втрата фокусу вікна, приховування сторінки чи destroy скасовують незавершений pull. Невеликий відступ, після якого загальна відстань усе ще не менша за 88px, залишає жест підтвердженим до відпускання.
- Якщо wheel повернувся всередину вмісту, поточна серія втрачає право на перехід. Два пальці скасовують pull і залишають pinch zoom браузеру.
- Поля, textarea, contenteditable, посилання, кнопки всередині вмісту, range/slider та вкладені scroll-контейнери не використовуються як початок pull/wheel-навігації. Додаткове виключення: `data-pg-navigation-ignore`.
- Перетягування мишкою на самому тексті залишається виділенням. Смуга прокручування зберігає свою поведінку.
- Коротка секція доступна в обох напрямках через ручки, кнопки та нові wheel/сенсорні жести. На першій / останній межі недоступна кнопка disabled.
- Зміна секції приховує панель через hidden, зберігає DOM, значення полів і scrollTop кожної панелі. Перехід сам нічого не зберігає на сервері.
- Клавіатурний / кнопковий перехід фокусує заголовок. Gesture-перехід не переносить зовнішній фокус; фокус усередині прихованої панелі завжди переводиться на видимий заголовок. Live region повідомляє лише завершені зміни / помилку, без озвучування кожного кадру прогресу.

## Архітектура й API

| Файл | Одна відповідальність |
| --- | --- |
| `src/ui/section-navigator/pull-state.js` | Чиста математика межі, дельт і порога; Node-тести |
| `src/ui/section-navigator/navigation-gestures.js` | Локальні wheel, Touch Events і Pointer Events; повертає cleanup |
| `src/ui/section-navigator/section-navigator.js` | DOM, порядок секцій, callbacks, фокус та lifecycle |
| `src/ui/section-navigator/section-navigator.css` | Тільки власні pg-section-navigator стилі, існуючі токени |

```js
import { createSectionNavigator } from './src/ui/section-navigator/section-navigator.js';
import './src/ui/section-navigator/section-navigator.css';

const navigator = createSectionNavigator({
  label: 'Блоки товару',
  items: [
    { id: 'main', label: 'Основне', content: mainEditor.element },
    { id: 'photos', label: 'Фото', content: photoEditor.element },
  ],
  initialId: 'main',
  wheel: true,
  // Власник вирішує, чи можна перейти; компонент не імпортує редактори.
  canNavigate: async ({ fromId, toId, source }) => true,
  onChange: ({ fromId, toId, source }) => {},
  onError: (error) => {},
});
host.append(navigator.element);
await navigator.navigate('photos'); // Promise<boolean>
navigator.getActive(); // 'photos'
// Спочатку прибрати навігатор, потім destroy самих редакторів у їхнього власника.
navigator.destroy();
```

`label`, непорожній масив items, унікальні kebab-case id, непорожні label та різні HTMLElement content обов'язкові. `initialId` за замовчуванням — перший id. `wheel` вимикає тільки wheel-навігацію; звичайне прокручування залишається. `navigate(id, { focus = true } = {})` повертає false для поточного / невідомого id, busy, denied або destroyed. API та кнопка можуть перейти без досягнення межі; умова межі стосується жесту продовження скролу.

`source`: `api`, `button`, `pointer`, `touch`, `wheel`. `canNavigate` повертає boolean або Promise<boolean>. Поки очікуємо, aria-busy=true, повторні переходи заблоковані. false залишає поточну секцію й показує короткий локальний статус. Виняток показує локальну помилку та викликає onError. Пізній результат після destroy ігнорується. Callback onChange викликається один раз після зміни, початковий mount його не викликає.

Жодних залежностей від Shell, router, інших features, локального сховища чи зовнішніх UI-бібліотек. Розмір задається контейнером через успадковану CSS-змінну `--pg-section-navigator-height` (типово `min(440px, 65dvh)`). Навігатор сам імпортує тільки свої JS-файли; CSS підключає власник. Destroy прибирає слухачі, таймери та власний DOM; редактори / їхні callbacks лишаються відповідальністю власника.

## Перевірка та межі

Node-тести: нормалізація wheel, fractional / negative scrollTop, малі секції, поріг та відкат. Браузерні тести: межі, інерція, кнопки й клавіатура, форма / вкладений скрол, скасування, scroll / DOM persistence, async guard, два екземпляри, destroy, мобільна ширина, тема, reduced motion. Окремі реальні дотики перевіряються через браузерну емуляцію; перевірка на фізичному iOS Safari залишається платформною ручною перевіркою. За відсутності cancelable gesture кнопки завжди залишаються робочим шляхом.

Демо: `/tools` → «Переходи», незалежні блоки «Основне», «Фото», «Опис». Це приклад вмісту, який можна замінити DOM будь-якого редактора; продукційний модуль товарів не створюється цією зміною.

## Поточний контракт: 9 листопада 2026 — повна робоча область

Вкладка `/tools → Переходи` монтує `navigationDemo.element` безпосередньо в native `pg-tabs__panel`. Немає додаткового `createPageView`, demo-wrapper, вкладеної картки або другого скролу. `navigator.setScrollContainer(panel)` підключає до однієї нативної робочої області обробку колеса/дотику; `viewport` в external-mode не скролиться сам.

**Два контрольні елементи:** верхній `previous`, нижній `next`, завжди біля правої межі. Малий круг зі стрілкою — **32 CSS px**. Підпис з назвою сусідньої секції розташований **ліворуч** від круга, без «Назад»/«Далі». На крайніх секціях недоступна стрілка залишається в приглушеному disabled-стані.

**Прогрес:** кожна стрілка має власний SVG-ring. Воно показує **лише відтяжку на відповідній межі**: накопичення wheel на 180 CSS px, touch/pointer на 88 CSS px. Звичайне `scrollTop` не змінює кільце. Зупинка/скасування жесту скидає індикатор; підтверджений жест переключає секцію після порога. Збережені wheel idle 200 ms, cooldown 600 ms та захист інерції.

**Перехід:** незалежний вміст виходить fade+translate (170 ms), наступний з’являється fade+translate (270 ms). Напрямок відповідає переходу вперед/назад. У `prefers-reduced-motion` просторовий рух пропускається. DOM, поля, focus management, guards, callbacks, позиції прокрутки й destroy залишаються під контролем модуля.

Початкове дослідження у верхній частині документа описує історичні компроміси та пороги. Старі припущення про `440px`, великі панелі й індикатор від `scrollTop` для поточного UI більше **не застосовуються**.


## Корекція відступів і курсора — 2026-11-09

Зайвий горизонтальний відступ виникав через повторне застосування `--pg-workspace-gutter` усередині вкладки. Тепер єдина локальна величина `--pg-section-inset: var(--pg-space-4)` використовується для header, viewport та обох стрілок: лівий край назви й форми співпадають, праворуч аналогічна геометрія.

Раніше `minmax(0,1fr)` у grid та `min-block-size:100%` заповнювали порожнечею короткий розділ. Для `data-pg-scroll-container=external` використовуються чотири auto-рядки без min-height. Нижня стрілка тепер стоїть після фактичного вмісту. Робоча область Shell зберігає свій розмір, але навігатор не додає штучний порожній розділ.

Курсор над керуванням стандартний (`default`), а не `grab/grabbing`; pointer drag для відтяжки й натискання залишаються доступними. Кільця показують тільки pull-прогрес.

## Розмір зовнішньої робочої області — уточнення 2026-11-10

У `data-pg-scroll-container="external"` (спільна робоча область вкладки або Workspace Dialog) короткий розділ тепер розтягується **щонайменше на всю доступну висоту**, а кнопка наступного розділу залишається **внизу**. Верхня кнопка — біля початку. Для довгого вмісту контейнер може рости за min-content, а обидві рейки використовують свій наявний sticky-механізм у тому самому нативному зовнішньому скролі.

Окремої прокрутки для короткого вмісту, другого navigator, меню або нового керування немає. Це змінює попереднє тимчасове правило «нижня кнопка відразу після короткого контенту»; тепер воно **не застосовується**. Реалізація тільки у shared `src/ui/section-navigator/section-navigator.css`; перевірка `tests/e2e/section-navigator.spec.js`.

## Універсальна двоколонна геометрія — 2026-11-11

Остання глобальна вимога скасовує старі чотири рядки (header / top-rail / content / bottom-rail): **ніяких 38px горизонтальних смуг для стрілок**. Спільний навігатор має два grid-стовпці: `minmax(0, 1fr)` під заголовок/вміст та вузький правий стовпець під стрілки. Два рядки: header і контент. Верхня стрілка займає перетин header/right, нижня — content/right біля нижньої межі. Підписи сусідніх секцій розкриваються ліворуч від круглої кнопки, не створюючи повноширинної смуги.

Геометрія **без вкладених відступів**: header і viewport мають `padding-inline: 0`; вони займають **всю** робочу ширину. Внутрішній viewport прокручує тільки контент, стрілки накладаються виключно на компактну праву ділянку свого верхнього/нижнього краю, без резервування вертикальної колонки під всю висоту. Спільний рядок заголовка має 56px — це дозволяє вирівняти його центр із першим пунктом локального меню Workspace (8px inset + 42px row). Зовнішній scroll-container лишається підтриманим для сторінок із однією вже наявною прокруткою; sticky нижньої стрілки не вносить окремий scroll layer. Жести, SVG-ring, анімація, статус і контракти `navigate` не змінюються. Усі ранні згадки про чотири окремі grid-рядки або смуги 38px — історичні.
 

## Дослідження: приховані центральні індикатори переходів — 2026-11-11

**Статус: запропоноване UX-рішення, ще НЕ реалізовано.** На прохання користувача глобально прибрано видимий числовий лічильник на кшталт `1 / 3` із `SectionNavigator` (JS + CSS); дані про активну секцію залишилися в назві, `aria-label` кнопок та прихованій live-region.

**Вибір:** два контекстні індикатори — верхній по центру власної робочої області для `previous`, нижній по центру для `next`. На початку вони не мають видимого графічного сліду і не займають місця у потоці документа. З'являється **лише відповідний напрямок**, коли користувач продовжує колесом або дотиком прокручувати вже досягнуту межу секції. Фактичний прогрес малює **те саме існуюче SVG-кільце**. Звичайний scroll всередині довгого вмісту не викликає індикаторів. Останній/перший розділ не показують недоступного напрямку.

### Оцінка альтернатив

1. **Завжди видимі справа (поточний стан):** помітно, але елементи конкурують із заголовком, полями й кутовими командами редактора; вимагають окремого правого grid-стовпця й складно вирівнюються між різними робочими контейнерами.
2. **Завжди видимі по центру:** виправляє симетрію, однак залишається зайвий постійний UI над формою.
3. **По центру й контекстно, під час boundary-pull:** рекомендовано, бо чиста робоча область і однакове положення в сторінці/модалці. Потрібна передбачувана альтернативна навігація без жестів.
4. **CSS scroll-snap по всій висоті:** не обираємо: може заважати довгим формам, ручному scroll, селекції та внутрішнім scroller.

### Контракт появи та позиціонування

- Контейнер для розрахунку центру — **canvas/scrollport поточного `SectionNavigator`**, а не весь `window`, зовнішня модалка або панель навігації. Центр `50%` по горизонталі. Верхній індикатор — 12px від верхньої межі canvas, нижній — 12px від нижньої; уточнити на еталонному браузерному знімку, врахувавши safe-area.
- Розмістити як **overlay** поверх того самого scrollport: жодних нових рядків/стовпців Grid, нового wrapper для body, другого скролу, глобального `position: fixed`, нового FAB чи кнопки. Заголовок та вміст залишаються на єдиних рівних лівому/правому краях.
- Бездіяльність: `opacity:0`, візуально відсутній, `pointer-events:none`; `aria-label` і штатні кнопки/жести живуть у тому самому компоненті. Визначення «видимий» має враховувати `focus-visible` і доступну альтернативу дотику (нижче), без невидимого клавіатурного фокуса.
- `onProgress(direction,progress,source)` із наявного `navigation-gestures.js` уже дозволяє показувати індикатор без нового слухача wheel/touch. Показати при `progress > 0`, зростання кільця — незмінне. У разі `reset`, відкату, переходу, blur, cancel, знищення — сховати. Не чіпати пороги **180px wheel / 88px touch**, idle **200ms**, cooldown **600ms** і правило нового wheel burst після досягнення межі.
- Швидка поява без стрибка геометрії; коротка opacity-анімація з наявних motion tokens. `prefers-reduced-motion` — без transition/transform. Не додавати новий тип motion і не порушувати існуючу анімацію виходу/входу секції.
- Не перехоплювати звичайне колесо в textarea, select, полях, contenteditable чи nested-scrollers. Після успішного переходу обидва індикатори знову приховані.

### Обов'язкова доступність — винятки з візуального приховування

Повністю приховане керування при відсутності альтернативи погіршує discoverability і може лишити людей без мишачого колеса/жестів без доступу до секцій. Тому потрібні одночасно:
- **Клавіатура:** кнопки `previous/next` мають залишатися у Tab-порядку й одразу проявлятися при `:focus-visible`. Кільце фокуса видно весь час, поки є фокус; Enter/Space викликають той самий `navigate`. Ніяких `display:none` / `visibility:hidden` на focusable controls.
- **Мишка/дотик без перетягування:** використовується **вже наявне бічне меню перемикання секцій** — один click/tap по потрібному розділу. Воно є повноцінною альтернативою gesture-навігації та повинне залишатися доступним і з клавіатури. **Не створювати** додаткових крайових trigger-зон, другої навігації, кнопок або спеціального меню заради прихованих стрілок. Якщо конкретний екран не має такого меню, спершу перевірити його реальну навігаційну структуру, а не вигадувати новий control.
- **Без додаткової підказки за замовчуванням:** наявне бічне меню вже пояснює доступність розділів. Не додавати нові hint, лічильник `1/3` або інший постійний елемент без окремої вимоги.

### Перевірки після реалізації

1. Local viewport довгої секції: скрол усередині — індикаторів нема; нова wheel-серія після досягнення краю — нижня по центру; часткове кільце, скасування, підтвердження; після переходу приховано.
2. External/Workspace scrollport, розгорнутий/згорнутий Aside, desktop/mobile та велика/мала секція: центр **всередині canvas**, верх і низ симетричні, поля не стрибають, фіксовані header/footer модалки не перекривають індикаторів.
3. Перша/остання секція: недоступний напрямок не з'являється. Escape, втрачений фокус, другий pointer, inert background і повторний відклик мають скасовувати появу.
4. Keyboard Tab/:focus-visible, Enter/Space, reduced-motion, однаковий UI в обох інтеграціях, `SectionNavigator` один на робочу область, без додаткових touch/wheel handlers.

### Зовнішні джерела

- [Apple HIG — Scroll views](https://developer.apple.com/design/human-interface-guidelines/scroll-views): тимчасові індикатори під час прокручування, очевидна можливість скролу, нативні жести, уникнення вкладених однаково спрямованих scroll views.
- [MDN — overscroll-behavior](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/overscroll-behavior): контроль scroll chaining (не є механізмом переходів).
- [W3C WCAG 2.5.7 — Dragging Movements](https://www.w3.org/WAI/WCAG22/Understanding/dragging-movements): потрібна доступна single-pointer альтернатива власному drag.
- [W3C WCAG 2.1.1 — Keyboard](https://www.w3.org/WAI/WCAG22/Understanding/keyboard): доступність дії з клавіатури.
- [W3C WCAG 2.4.7 — Focus Visible](https://www.w3.org/WAI/WCAG22/Understanding/focus-visible): видимий фокус для keyboard control навіть якщо індикатор зазвичай прихований.

Цей розділ заміняє попередню ідею постійної правої смуги **лише як досліджуване рішення**. До окремої реалізації чинна геометрія залишається праворуч.
