# Scrollbar — дослідження legacy та контракт Pinguin Next

## Джерело у V5

- `legacy/css/foundation/scrollbar.css` застосовував `::-webkit-scrollbar` **глобально** до скрольованих областей: 10px, прозора доріжка, округлий повзунок і підсвічення під час hover. Окремої логіки прокручування чи JS-компонента не було.
- `legacy/css/layout/layout-body.css` приховував смугу прокручування в окремій `.section-content`; `legacy/css/components/tables/pseudo-table.css` користувався нативним `overflow-y: auto`. Не переносити локальне приховування на всі таблиці: індикатор прокручування потрібний.
- `legacy/css/layout/layout-footer.css` мав власний `border-top` для `.entity-footer`. Це історичний приклад, **не** вимога копіювати лінію у новий Shell.

## Реалізація у work

- Один спільний CSS API: `src/ui/scrollbar/scrollbar.css`, клас `.pg-scrollbar`. Цим класом уже користуються таблиця, плитки та інші скрольовані компоненти. Не створювати новий scrollbar, JS-обгортку чи локальні варіанти у features.
- Нативне прокручування мишкою, колесом, тачпадом, дотиком і клавіатурою зберігається. Повзунок видимий і доступний для перетягування; кнопки-стрілки браузера приховані.
- Chromium/WebKit: 8px, прозора доріжка, округлий повзунок із семантичних токенів, `::-webkit-scrollbar-button { display: none; width: 0; height: 0; }`.
- Firefox / браузери без повної підтримки WebKit-псевдоелементів: стандартні `scrollbar-width: thin` та `scrollbar-color`.
- **Несумісність:** `scrollbar-width: thin` або не-`auto` `scrollbar-color` переважають над `::-webkit-scrollbar-*` у браузерах, які підтримують обидва механізми. Тому всередині `@supports selector(::-webkit-scrollbar-thumb)` ці дві стандартні властивості повертаються до `auto`, інакше правила приховування стрілок не діють. Перевіряємо саме `-thumb`: часткова сумісність Firefox з базовим `::-webkit-scrollbar` не гарантує стилізацію повзунка.
- Джерело механіки: [MDN — scrollbar-width](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/scrollbar-width), [MDN — scrollbar-color](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/scrollbar-color).

## Нижня межа робочої області

- `src/shell/shell.css` — власник геометрії `.pg-shell__footer` та `.pg-shell__footer-panel`. Колишня суцільна лінія йшла від `border-top` панелі Footer, **не** від таблиці чи пагінації.
- За вимогою від 2026-11-10 Footer без верхньої декоративної лінії. Зберігаємо його структурну висоту 56px, єдину пагінацію посередині, page-size FAB праворуч, незалежний FAB Aside та анімацію RevealPanel.
- Не створювати окремого режиму Main і не змінювати стилі таблиці/пагінації, щоб приховати бордер Shell.

## Артефакт на перетині таблиці й Footer (2026-11-10)

На скриншоті під час прокручування таблиці біля її нижнього лівого краю з'являється фрагмент розміром близько 8×8px. Його розташування збігається з початком горизонтальної смуги прокручування. Найімовірніше, це нативна кнопка `::-webkit-scrollbar-button:horizontal:decrement`, яка у частині Chromium/Windows конфігурацій продовжує малювати системну піктограму, навіть якщо загальний селектор задає `display: none`. Без прямого браузерного відтворення це діагностична гіпотеза, не підтверджена причина.

Спільний scrollbar має забороняти і площу, і нативне оформлення кнопок у горизонтальному й вертикальному напрямках (зокрема `decrement`/`increment`), але **не** приховувати track/thumb і не вимикати прокручування. Рішення належить лише `src/ui/scrollbar/scrollbar.css`, не collection feature і не Shell. E2E перевіряє directional pseudo-elements, вертикальне та горизонтальне прокручування; остаточна перевірка появи піктограми вимагає візуального тесту у браузері, де її спостерігали.

## Перевірки

1. У Chromium на вкладці «Макети даних»: у таблиці є вертикальний скрол із видимим повзунком, **немає малих стрілок угорі/внизу**; drag/колесо/клавіатура прокручують.
2. У плитках та інших компонентах із `.pg-scrollbar`: той самий принцип і відсутність стрілок.
3. У Footer немає верхнього бордера, але зона залишається 56px, пагінація по центру, FAB в її правому краї; ліва/права панелі й світла/темна теми не змінені.
4. Запускати `npm run check`, `npm run test:e2e` і ручну перевірку desktop/mobile, якщо середовище доступне. Результати конкретних запусків вказувати окремо, без припущення, що опис дорівнює пройденому тесту.
