# Animated Gradient — безшовне колірне поле

**Гілка:** `work`. **Оновлено:** 2026-11-13. **Зовнішній API:** `createAnimatedGradient({text = 'pinguin V6'})`.

## Чому змінено renderer

Попередні шість CSS-радіальних плям були окремими **прямокутними DOM-шарами**, частково зсунутими за межі контейнера. Навіть якщо їхній radial gradient закінчувався прозорим, обрізана рамка самого шару залишалася видимою як вертикальна/горизонтальна лінія; порядок alpha-compositing давав перевагу останньому, червоному шару. Користувацький скріншот 13.11 підтвердив обидва дефекти. Просте розширення CSS-шарів прибирає шви, але в локальних візуальних пробах перетворює композицію на звичайну діагональну заливку.

**Рішення:** залишити той самий `AnimatedGradient`, замінити **внутрішній спосіб рендеру** на один Canvas 2D без сторонніх бібліотек. Піксельні кольори обчислюються як **нормалізоване зважене змішування** `main` / `secondary` / `tertiary`, на основі шести повільно рухомих центрів впливу, по два на кожний тон. Координати плавно викривлюються, тому немає ідеальних смуг, кіл, меж шарів і форм.

## Контракт

- Єдиний компонент `src/ui/animated-gradient/animated-gradient.js` створює один декоративний `canvas[aria-hidden=true]`; логіка пікселів ізольована у внутрішньому `src/ui/animated-gradient/color-field.js`. **Другого компонента, менеджера анімацій або модалки немає.**
- Колір береться виключно з наявних CSS токенів `--pg-tone-main-base`, `--pg-tone-secondary-base`, `--pg-tone-tertiary-base`; ні теми, ні ролі `main/secondary/tertiary` не змінено. Середні інтенсивності підбираються для рівного внеску трьох ролей, **не** обіцяють 33⅓% екранних пікселів точно заданого hue. `main` і `secondary` в чинній палітрі обидва сині.
- Один малий Canvas із роздільністю **від 72 до 140 px по кожній осі**, залежно від розміру поверхні; браузер розтягує його на весь компонент з білінійним згладжуванням. Плавне неперервне поле без внутрішніх геометричних швів.
- Максимальна частота **24 кадри/с**. Кожна каденція використовує 6 згладжених полів із дешевою раціональною функцією ваги, без `filter:blur()`, WebGL, `Math.exp` на кожному пікселі, CSS-анімації `background-position` або анімованого layout. Локальна ізольована проба з трьома полотнами по 120×114 займала **~3,35 мс сумарно на три малювання** у headless Chromium; це лише прототипний замір, не гарантований FPS на Windows і не вимірювання інтеграції сайту.
- `IntersectionObserver` зупиняє кадри поза видимою областю; `document.visibilitychange` — у неактивній вкладці; наявний `pg:modal-change` — коли поле під іншою модалкою; `prefers-reduced-motion` лишає статичний кадр. Усі спостерігачі, callback і RAF прибираються після від'єднання компонента.
- `ResizeObserver` перемальовує у відповідній роздільності; зміна `data-theme` переобчислює палітру і оновлює вже створений Canvas без заміни DOM.
- На випадок відмови Canvas 2D залишається суцільний fallback із трьох семантичних тонів у CSS.
- `text:null` — вміст **лише з кольору**, а пропущений `text` зберігає назву `pinguin V6` для інших споживачів. У демонстрації `Dialog` використовується наявне `presentation:'edge-to-edge'`, без шапки/футера й тільки з кнопкою закриття.
- Стандартний `showModal()` продовжує блокувати фоновий UI. Немає окремого modal/animation engine.

## Перевірка

- `tests/e2e/animated-gradient.spec.js` перевіряє повне заповнення Dialog, відсутність DOM-шарів зі швами, плавність суміжних пікселів Canvas, зміну кольору, dark theme, reduced motion, паузу/відновлення фонового полотна, Escape і повторне використання загального Dialog.
- Нові формули були **локально візуально перевірені** в ізольованій HTML-пробі на 440×420. Це не означає, що повний production Vite або Playwright прогін уже успішні; для цього потрібен окремий запуск.
