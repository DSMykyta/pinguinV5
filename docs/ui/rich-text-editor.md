# Rich Text Editor — універсальний редактор із дзеркальним переглядом

**Статус:** перша інтеграція в `work`, 2026-11-09. **Не** замінює `src/ui/textarea`. Детальний аналіз — [дослідження](../research/rich-text-editor.md). Див. [конвенції](../conventions.md).

## Мета
Самостійний WYSIWYG для довгих форматованих описів товарів, статей та іншого rich text. Дзеркальний вигляд — **читабельна синхронна read-only проєкція** редактора, а не друга редагована область. Перемикається між оформленим текстом та екранованим HTML-кодом. Один структурний документ, одна історія змін, одне джерело правди.

## API
`createRichTextEditor(host, { content?, editable?, toolbar?, mirror?, stats?, extensions?, onChange? })`.
Повертає `{ element, getJSON, getHTML, getText, setContent, setEditable, focus, clear, on, destroy }`.
- `content` — HTML або Tiptap JSON; `getJSON()` — канонічна структура документа; HTML — представлення.
- `onChange({ json, html, text })` спрацьовує на зміну документа.
- `toolbar`, `mirror`, `stats` незалежно вмикають або вимикають відповідні UI-можливості.
- `destroy()` знімає підписки і DOM лише цього екземпляра; повторний виклик безпечний.
- Не створює window globals і не читає сторонні сторінки/стани.

## Розміщення і модульність
`src/ui/rich-text-editor/rich-text-editor.js` — композиційний модуль. `engine.js` — Tiptap/ProseMirror. `sanitize.js` — HTML межа. `toolbar.js`, `mirror.js`, `stats.js` — опційні функції, які отримують лише `editor`, `container`, повертають `dispose()`. `text-stats.js` — чиста функція. `rich-text-editor.css` — лише стилі компонента. Демонстрація окремо у `src/features/tools/rich-text-editor-demo.js`.

Ніяких імпортів між опційними функціями. Shell не знає про редактор. Багато екземплярів ізольовані один від одного.

## UX і безпека
Тема й відступи успадковуються від наявних `--pg-*` токенів; доступні кнопки, `aria-pressed`, `focus-visible`, reduced motion, вертикальний layout на вузькому екрані. Редагований DOM веде ProseMirror, не виконуємо `execCommand()`. Paste/HTML нормалізується DOMPurify та schema редактора, HTML в mirror санітизовано. Для серверного збереження потрібна **незалежна серверна** валідація. Немає автозбереження за замовчуванням.

## Критерії і подальші блоки
- Перевірити форматування, списки, undo/redo, перемикання HTML/вигляд, читабельність у двох темах.
- Перевірити порожній контент, вставку з Word/HTML, IME, мобільну клавіатуру, selection, несанкціонований HTML.
- Потенційні незалежні майбутні можливості: find/replace, валідація заборонених слів, макроси, режим редагування джерела через CodeMirror, документні пресети/збереження. Нічого з цього не оголошено готовим.

Використано стабільний Tiptap 3, DOMPurify. Версії зафіксовані в `package.json`. Потрібно виконати `npm install`, `npm run check` та `npm run test:e2e` у середовищі з доступом до npm і браузера.
