# Rich Text Editor — режими «Редактор» та «HTML»

**Процесні вимоги, тести, відкриті проблеми:** [зведені правила проєкту](../implementation-rules.md). Режимний перемикач повторно використовує спільний `createSegmentSwitch()`; `mode.js` є лише адаптером стану редактора. Панель форматування використовує `createIconButton({ variant: 'mini' })` та `createRevealPanel()`.

**Статус:** реалізація в `work`, 2026-11-09. [Дослідження](../research/rich-text-editor.md). Окремий `src/ui/textarea` залишається для plain-text полів.

## Суть

Одна робоча область, **два взаємовиключні режими**, а не дві паралельні колонки. **«Редактор»** — WYSIWYG `contenteditable` із панеллю форматування (жирний, курсив, підкреслення, абзац, H1–H3, списки, цитата); **«HTML»** — повноцінно редагована `textarea` з вихідним HTML цього документа. Нативний перемикач зі спільною sliding plate показує **дві іконки «текст / код»** (доступні назви «Редактор / HTML») у верхньому лівому куті. Поряд розташована компактна кнопка `>` того самого класу висоти, яка розкриває кнопки форматування у тому самому полі. За замовчуванням дії приховані. Розкриття не створює додаткової рамки, фону чи другого редактора. Статистика символів і слів лишається внизу. Редагування HTML не перемальовується на кожну клавішу: чернетка зберігає курсор і рідний undo. Повернення до візуального режиму застосовує санітизований код; експорт у будь-якому режимі очищує HTML.

## API

`createRichTextEditor({ content?, editable?, toolbar?, code?, stats?, label?, onChange?, onModeChange? })` повертає **непідключений** екземпляр:

`{ element, input, source, getMode(), setMode('editor'|'html'), getHTML(), getText(), getSource(), setHTML(html), setEditable(boolean), focus(), execute(command), clear(), destroy() }`.

- `code: true` за замовчуванням; `code: false` прибирає перемикач та HTML-режим, якщо потрібне звичайне поле rich text.
- `toolbar` і `stats` не залежать від режимного перемикача; `toolbar: false` не вимикає можливість вибрати HTML.
- `onChange({ html, text, mode })` — зміна змісту; `onModeChange(mode)` — завершене перемикання. Компонент не зберігає даних у сховище.
- `getSource()` у HTML-режимі повертає **сирий код чернетки**, `getHTML()` — **очищений HTML**. Якщо код містить недопустимі теги/атрибути, під час переходу в редактор вони видаляються з повідомленням.
- `setEditable(false)` встановлює `contenteditable="false"` і `textarea.readOnly`; перемикання режимів доступне для перегляду.
- Історія `undo/redo` в WYSIWYG локальна; у HTML-режимі працює нативний undo/redo браузерної `textarea`. Вихід із HTML створює запис у WYSIWYG history, тож зміна з коду може бути скасована після повернення.

## Структура / LEGO

- `rich-text-editor.js` — композиція та єдине джерело режиму, публічне API й очищення ресурсів.
- `mode.js` — тонкий адаптер над `src/ui/segment-switch`, знає лише `getMode`, `setMode`, `subscribe`.
- `toolbar.js` — спільні SVG `IconButton` 32×32, `RevealPanel` для розкриття і кнопка зі стрілкою; форматування автоматично вимикається у HTML-режимі. Дії мають доступні назви, `aria-pressed` і навігацію стрілками/Home/End.
- `commands.js` — обмежені `Selection`/`Range` команди, без deprecated `execCommand`.
- `history.js` — історія візуального редагування.
- `html.js` — дозволені HTML-теги/атрибути та безпечний імпорт/експорт (не використовує сторонніх npm пакетів).
- `stats.js` — незалежна статистика тексту в обох режимах.
- `rich-text-editor.css` — геометрія єдиної рамки й розташування контролів; вигляд кнопок і анімація розкриття залишаються власністю спільних компонентів і токенів `--pg-*`.
- `src/features/tools/rich-text-editor-demo.js` — приклад у вкладці `/tools` → «Текст». Shell та інші UI не імпортують редактор.

## Вставка HTML з буфера

У режимі **«Редактор»** HTML із MIME `text/html` вставляється як оформлений текст після очищення. HTML, скопійований саме як код із генератора, textarea чи блока коду, часто надходить у форматі `text/plain`. Незалежний `paste.js` розпізнає завершені фрагменти розмітки та перетворює їх на оформлений документ через існуючий `parseSafeHtml()`. Звичайний текст із символом `<` не змінюється.

В **«HTML»** вставка лишається нативною для textarea: код не перетворюється на вигляд до перемикання назад. `paste.js` має власний `dispose()`, не імпортує Shell або інші UI адаптери й не потребує нових npm-пакетів.

## Обмеження

Native editing — це контрольований старт, не повноцінна заміна ProseMirror: підтримка багатоблочних selections, складної вкладеної HTML-розмітки, IME, undo в усіх браузерах та імпорту Word має додаткові ризики. Сторонній HTML очищується суворим allowlist; CSS, скрипти, iframe, зображення та непідтримувані атрибути не переносяться між режимами. Окреме серверне очищення **обов'язкове** для зберігання й публікації. Автозбереження, пошук/заміна та перевірка слів — майбутні незалежні «шарми», не частина поточного ядра.

## Перевірка

`node --test src/ui/rich-text-editor/*.test.js`, `npm run check`, `npm run test:e2e`. Браузерні сценарії мають покрити: введення у WYSIWYG → HTML, редагування коду → рендер, спробу XSS, undo після повернення, source-native undo, роздільність екземплярів, disabled, клавіатуру, мобільну ширину.

## Компактна панель — дослідження та критерії (2026-11-12)

За основу взято принцип **контекстних дій** з [Material 3 Docked/Floating Toolbars](https://github.com/material-components/material-components-android/blob/master/docs/components/DockedFloatingToolbars.md), але для редактора прийнято **inline-композицію у межах поля** замість окремого плаваючого чи закріпленого контейнера. Це відповідає вимозі одного контуру й не створює непотрібного нового спільного Toolbar.

- Передній лівий елемент — наявний `createSegmentSwitch` з **`filled` pill-треком і рухомою плашкою**, дві іконки `file-text` і `code`; початковий режим `editor`. Клік на сегмент переводить у той самий HTML-документ, а не відкриває нове поле. `outline` навколо цього перемикача не потрібен.
- Наступний елемент — спільна мінікнопка `chevron-right`, яка перемикає `aria-expanded`. Стан `data-pg-disclosure` існуючої мінікнопки у спільному Button плавно повертає іконку на 90° із чинними motion-токенами; `prefers-reduced-motion` вимикає поворотний перехід. Розкриття самої панелі — наявний `RevealPanel`.
- Форматування — **Material 3 Floating Toolbar**: спільний `configureToolbar(element, {variant:'floating', density:'compact'})` із округлою капсулою, м'якою поверхнею та проміжками 4px. Усередині ті самі 12 мінікнопок із [Material Symbols Rounded](https://github.com/google/material-design-icons/tree/master/symbols/web). Їхній hover, selected і disabled стан не дублюються в редакторі. Інші компоненти можуть використати `src/ui/toolbar` без знання про редактор.
- Єдина **зовнішня рамка** навколо перемикача, стрілки, тексту/HTML та нижньої статистики. Зелений `focus-within` обвід поля видалений; keyboard-focus залишається видимим на інтерактивних контролах. Між верхніми контролами й введенням немає розділової лінії. Панель дій має M3-подібну **капсулу-підкладку, без окремого border**. **Оновлено 2026-11-13:** `tools-host` стоїть **у рядку перед стрілкою**, а не в абсолютному overlay під нею; висота header зарезервована, тому текст, статистика й зовнішня рамка не зсуваються. На вузьких екранах панель прокручується горизонтально, не переносячи кнопки на другий рядок.
- У HTML-режимі кнопки форматування disabled, а **стрілка і панель приховані**; сира HTML-чернетка й нативний undo не змінюються. Перевірки тексту надалі можна приєднати незалежно, не пов'язуючи їх із Toolbar.
- `toolbar: false` ховає стрілку й панель; `code: false` ховає перемикач; `stats: false` не показує статистику. Усі ці параметри працюють незалежно.
- Приймання: перевірити розгортання й згортання, режим текст/HTML, форматування виділення, клавіатуру, скринридер, 390px, теми, reduced motion і незмінну статистику.

**Уточнення дизайну (2026-11-12):** після першої інтеграції власник відхилив зелену рамку фокусу редактора, миттєву зміну стрілки та непідкладені іконки. Тому сфокусоване поле не змінює border, стрілка використовує спільний disclosure motion, перемикач — filled slider, а форматування — контекстну капсулу Floating Toolbar згідно з [M3 Docked/Floating Toolbars](https://github.com/material-components/material-components-android/blob/master/docs/components/DockedFloatingToolbars.md). 32px дії збережені згідно з побажанням компактності, хоча офіційний floating toolbar використовує більші touch targets.

## Уточнення від 2026-11-13 — розташування та HTML-режим

- Рядок керування у візуальному режимі: **перемикач → розкрита група форматування → стрілка**. Група стоїть **ліворуч від стрілки**, горизонтально в тому самому рядку; не накладається другим рядком під нею. Для вузького контейнера група прокручується горизонтально, а стрілка залишається доступною.
- У режимі HTML стрілка й панель форматування повністю приховані; відкрита панель закривається під час перемикання. Повернення до редактора відновлює стрілку, але не розкриває панель самовільно.
- **Спільний контракт поверхні коду:** кожне поле з перемиканням у режим коду використовує клас `pg-code-surface` на власній поверхні та `pg-code-surface__input` на полі коду. Стан читається зі стандартного `data-pg-mode='html'|'code'` у батьківському компоненті, без дублювання JS-стану. У кодовому режимі змінюється фон і контраст **усього контейнера**, вміст стає моноширинним. Кольори та шрифт — спільні токени; оформлення — у `src/ui/code-surface/code-surface.css`.
- Редагування HTML, native undo/redo, санітизація, нижня статистика і життєвий цикл редактора залишаються без змін.
