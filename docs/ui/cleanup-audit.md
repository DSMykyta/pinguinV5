# Аудит очищення компонентів /tools — 2026-11-10

## Межа

Аудит стосується поточної гілки `work`: реальні компоненти `src/ui`, демонстрації `src/features/tools`, Shell і відповідні тести. `main`, `legacy` та `reserve` не змінюються. Прикладні дані не є базою продуктів і не записуються на сервер.

## Залишені універсальні механізми

| Механізм | Джерело істини | Як перевіряється на сторінці |
| --- | --- | --- |
| Кнопка, мінікнопка, кольорові ролі, busy/loading | `src/ui/button` | Дії колекції, Menu, Dialog; окремий loading-preview для ще не інтегрованих асинхронних операцій |
| Dialog, Confirm та Form Dialog | `src/ui/dialog`, `src/ui/form-dialog` | Інформаційний Dialog, редагування запису й підтвердження його видалення |
| Вибір одного / кількох записів | `src/ui/collection-view`, `src/ui/selection-actions` | Таблиця брендів і незалежна медіатека |
| Меню, checkbox, поля, сегменти | відповідні каталоги `src/ui` | Реальні контролі в колекціях, редакторі та демо полів |
| Пагінація, Footer і єдина FAB | `src/ui/pagination`, `src/shell` | Обидві незалежні колекції |
| Toast | `src/ui/toast` | Один виклик у `Таблиці`, не у Shell |
| Редактор / HTML | `src/ui/rich-text-editor`, `src/ui/segment-switch` | Режимний перемикач одного документа у вкладці `Текст` |

## Прибрані дублікати і застаріле

- Окрема кнопка «Тест Confirm»: дублювала реальне видалення вибраних записів.
- Зайві `pg-dialog__button--*` класи й локальне стилювання disabled/hidden: оформлення звичайної кнопки залишається лише в `src/ui/button/button.css`.
- Прихована кнопка discard у звичайному Dialog/Confirm: тепер вона створюється тільки для діалогу з `closeGuard`.
- Дубль алгоритму «Дублювати бренд» у row menu та selection toolbar: одна локальна функція.
- Неіснуючий контракт `onClear` у Media Library selection toolbar: вилучений.
- Окремий стиль видалення у медіатеці: дія `delete` тепер використовує `danger/soft` та той самий Confirm з `danger/solid`, що і таблиця брендів.
- Два ручні шаблони редакторського діалогу переведено на наявний `showFormDialog`.
- E2E більше не створює додатковий кнопковий DOM для перевірки mini: перевіряється чинна кнопка pin. Confirm перевіряється на фактичних операціях.
- Історично застарілі примітки про власні кнопки `rich-text-editor/mode.js` оновлено відповідно до фактичного `createSegmentSwitch`.

## Що **не** є універсальним механізмом

1. **Збереження, архівація, дублювання та видалення записів у базі.** Наразі реалізовані лише локальні операції над масивами демонстрацій. `Dialog` і `SelectionActions` універсальні; зміни даних — відповідальність конкретного feature. API/backend і транзакційний сервіс відсутні.
2. **Генератор таблиць зі старої V5.** Вкладка `Таблиці` наразі слугує місцем для перевірки Toast, а не повним редактором або генератором. `CollectionView` є незалежним готовим UI-елементом, але це інша функція.
3. **Сама медіатека як бізнес-сервіс.** `media-library-demo` генерує SVG-зображення локально і є fixture для `CollectionView`; немає єдиного сховища, upload API чи синхронізації із сервером.
4. **Демонстраційні секції `src/features/tools/*-demo.js`.** Вони є прикладами використання компонента, не другим компонентним API. Їхні зразкові записи та тексти не слід переносити як глобальні налаштування.
5. **Вирівнювання особливих feature-політик при підтвердженні.** Формат тексту попередження, рішення про кількість вибраних та фактична зміна/відкат даних усе ще належать власнику колекції; централізація цих бізнес-операцій без конкретного backend-контракту не потрібна.

## Перевірки

Статичний контроль — `npm run check`, браузерна інтеграція — `npm run test:e2e`. Насамперед перевіряти: 1→2→1 вибраних, Cancel/Escape/Confirm, повернення фокусу, `danger/soft` і `danger/solid`, loading async confirm, незалежність вкладок та обох колекцій. Наявність test-файлів **не** означає, що вони виконані: фактичний результат CI фіксується окремо для конкретного коміту.
