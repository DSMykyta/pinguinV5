# Pinguin Next — типи сторінок та навігація, v1

**Статус:** контракт для \`work\`. Типи визначені; реалізовано «Огляд» і тестову сторінку «Інструменти» з локальними вкладками «Таблиці» та «Текст». Майбутні інструменти не створюються як порожні кнопки.

## 1. Один Shell, п'ять типів вмісту

| Type ID | Призначення | Ширина та структура | Приклади майбутніх сторінок |
|---|---|---|---|
| \`overview\` | початкова сторінка | спокійна основна область | Огляд |
| \`tool\` | виконання однієї задачі | спільна сторінка з робочою секцією | Генератор таблиць, текст, зображення |
| \`collection\` | робота зі списком об'єктів | список у спільному шаблоні | Товари, бренди, завдання |
| \`record\` | один об'єкт із редагуванням | форма в спільному шаблоні | Картка товару |
| \`settings\` | параметри / підключення | компактна форма | Параметри інтеграцій |

Тип не створює інший фон, sidebar чи набір дизайн-токенів. Усі користуються **однією оболонкою і чотирма кутами**.

## 2. Два рівні навігації

**Global navigation (лівий sidebar):** лише зареєстровані готові розділи або інструменти, доступні користувачу. Кожен має стабільний маршрут, назву, іконку і явний порядок. Активний пункт підсвічується за маршрутом, а не за назвою HTML-файлу чи CSS-класом.

**Local navigation (всередині сторінки):** вкладки та режими конкретного інструмента. Вкладки — частина вмісту модуля, а не глобального Shell. Немає глобального третього меню та дублювання однакових заголовків.

- Якщо це лише **режим одного редактора** (наприклад, відображення HTML/BR результату), стан можна тримати локально.
- Якщо це **окремий повноцінний екран**, яким потрібно ділитися через посилання, він отримує власний маршрут. Наприклад, у майбутньому \`/products\` і \`/products/product-id\` (параметризовані маршрути ще не реалізовані).
- Вкладки створюються як окремий спільний компонент \`src/ui/tabs\`, коли з'явиться перший інструмент, який їх потребує. Не робити їх заздалегідь як декорацію.

## 3. Контекст, заголовки й чотири кути

- **Вгорі ліворуч:** кругла кнопка навігації, без змін.
- **Вгорі у робочій області:** компактна назва поточної сторінки; вкладені записи згодом можуть мати «Назад»/шлях, але тільки коли це виправдано.
- **Вгорі праворуч:** кнопка контекстного popover. Надалі вміст popover визначається активною сторінкою, не її типом.
- **Внизу ліворуч:** тема в точній поведінці legacy.
- **Внизу праворуч:** лише дійсна швидка дія активного інструмента, якщо така існує; без порожнього FAB.

## 4. Маніфест сторінки

\`src/features/<id>/manifest.js\`:

~~~js
export const manifest = {
  id: 'table-generator',
  title: 'Таблиці',
  route: '/table-generator',
  type: 'tool',
  navigation: { icon: 'table-2', order: 10 },
  load: () => import('./index.js'),
};
~~~

Це **приклад контракту**, не активний пункт меню. Наразі зареєстровано лише \`overview\`.

- \`src/app/page-types.js\` — перелік типів.
- \`src/app/page-registry.js\` — єдине джерело сторінок: валідація ID, типу, URL, load(), навігація.
- \`src/app/router.js\` — History API, popstate, без прив'язки до DOM.
- \`src/shell/shell.js\` — викликає mount() сторінки, передає AbortSignal та викликає cleanup під час виходу; оновлює назву, \`document.title\`, стан навігації та області вмісту.
- \`src/shell/sidebar/sidebar.js\` — просто відображає пункти з реєстру; не знає, як працюють окремі модулі.

## 5. Правила навігації

1. Клік без модифікаторів використовує client-side routing; Cmd/Ctrl+клік залишає звичайну поведінку відкриття в новій вкладці.
2. Навігація за \`window.history\` забезпечує Back/Forward, прямі URL та оновлення сторінки (Vercel rewrite до index.html).
3. Незнайомий шлях показує «Сторінку не знайдено» з реальним посиланням на головну, без порожньої заглушки в sidebar.
4. Кожна сторінка монтується один раз, повертає функцію cleanup і має \`AbortSignal\` для скасування асинхронної роботи.
5. Під час зміни маршруту закривається контекстний popover та мобільне меню; глобальна тема й ширина sidebar зберігаються.
6. Маршрути не повинні читати чи змінювати робочі дані без явно підключених сервісів.
7. Якщо завантаження модуля не вдалось, Shell показує зрозуміле повідомлення, а не порожній екран.

## 6. Межі поточного етапу

- Немає генератора таблиць, фільтрів, вкладок і форм, поки не погоджено їхню поведінку.
- Немає авторизаційних груп та вкладених маршрутів із параметрами; їх додаємо перед відповідними реальними потребами.
- Context popover поки містить два дійсні посилання на документацію, не фіктивні кнопки.
- Жодних кольорових фонів для різних типів сторінок або «dashboard»-карток.
- Перед створенням першого нового інструмента потрібно перевірити його URL, тип, локальну навігацію, дії й сценарій повернення.

**Наступна функціональна задача:** генератор таблиць. Для нього необхідно погодити модель рядка, редактор, типи заголовків та два експортери; тільки після цього додати \`table-generator\` до реєстру.

## 7. Тест локальної навігації

У `work` зареєстровано `/tools`: окремий інструментальний екран з вкладками «Таблиці» та «Текст». Це перевірка навігації (не готові генератори). Вкладки реалізовано в `src/ui/tabs`; кожна вкладка має власний `tabpanel`, клавіатурне перемикання стрілками, Home та End. Активна вкладка передає контекст через `setAsideContext` у Shell; aside змінює заголовок і реальні посилання на старі модулі, але не змінює стилі чи розміри. Закріплений aside залишається відкритим при переходах між сторінками та перемиканні вкладок.

## 8. Вкладки у верхній частині — відновлений вигляд legacy

Локальна навігація сторінки «Інструменти» підключається до слотa `pg-shell__local-nav` у спільному header, але сам механізм вкладок залишається незалежним (`src/ui/tabs`). Як і `btn-icon.expand` у `legacy`, неактивна вкладка виглядає як кругла кнопка з іконкою. При наведенні та фокусуванні вона плавно розгортає підпис. Активна вкладка завжди має видимий підпис на м'якій капсульній підкладці. Дизайн повторює компактні пропорції прикладу (кнопка 32px); кольори задаються тільки токенами. У мобільному layout елементи залишаються між двома кутовими кнопками; після навігації слот очищується. Reduced motion вимикає анімацію.

## 9. Глобальне центрування навігації — як у legacy

Центрується **весь ряд вкладок** спільним `src/shell/shell.css` відносно вікна браузера (`left: 50%`, `translateX(-50%)`). Його центр залишається незмінним при згортанні sidebar чи закріпленні aside.

Кнопки **не мають окремих центрів, слотів чи фіксованих зарезервованих ширин**. Як у `legacy/css/layout/layout-nav.css`, контейнер має `width: fit-content` і звичайний flex-порядок. Кожна кнопка, як `.btn-icon.expand` у `legacy/css/components/buttons/button-icon.css`, плавно розгортає підпис **праворуч від іконки**. Через зміну загальної ширини ряд розсувається симетрично навколо свого центра, а кнопки природно рухаються разом із ним. Всі наступні інструменти використовують цей глобальний механізм без додаткових налаштувань.

## 10. Єдине розміщення назв і заголовків

Усі сторінки створюються за допомогою `createPageView()` з `src/ui/page`. Саме цей компонент визначає горизонтальне центрування, максимальну ширину (800 px) і типографіку H1. У верхній шапці є постійний елемент назви маршруту: «Огляд» або «Інструменти · Таблиці/Текст». Зміна вкладки оновлює його через callback `setPageSection()`, а не через додатковий заголовок або CSS-виняток. Повний контракт і CSS-власність див. [universal-page-layout.md](universal-page-layout.md).
